## 一、任务边界

任务1的目标是形成多款游戏的可复查运行结果，证明已经实际发现并分类兼容性或性能问题。它不要求在这一阶段修复所有发现的问题。

Dave 的启动、稳定性和输入修复属于任务2深度；Dave 的性能基线与优化前后对比属于任务3。两者可以作为任务1的证据来源，但不能替代“各种游戏”的覆盖要求。

## 二、完成标准

满足以下条件后，任务1才标记为完成：

1. 对四款游戏各完成至少一轮有效真机启动测试：Dave the Diver、Stardew Valley、Escape from Duckov，以及用于替代当前无法测试的 Palworld 的《合金装备5：原爆点》。若主候选无法取得合法、干净的 PC 副本，则改用《师父》作为第四款。

### T1-DUCKOV-A：Duckov 标准基线

1. 新建独立容器并记录容器 ID，不复制 Dave 或星露谷容器。
2. 设置公共基线、DXVK 3.0.2 和 `BOX64_UNITYPLAYER=1`，为 `Duckov.exe` 创建快捷方式，不添加启动参数。
3. 冷启动一次，最多等待 5 分钟；记录是否出现窗口、Logo、主菜单、读档/新游戏和实际场景。

6. 只有 A 轮日志表明进程已进入图形初始化但没有首帧时，才安排 T1-DUCKOV-B 的 WineD3D 单变量对照。

### T1-DUCKOV-B：WineD3D 单变量对照

1. 复用 A 轮容器、prefix、游戏文件和快捷方式配置，只把 DX wrapper 从 DXVK 3.0.2 切换为 WineD3D；Wine、Box64、Turnip/Zink、分辨率、HUD 与环境变量保持不变。
2. 执行参数填写 `-logFile Player-T1-DUCKOV-B.log`，不加引号。该参数仅把 Unity 日志输出到游戏工作目录，作为观测手段；WineD3D 是本轮唯一预期影响兼容行为的变量。
3. 冷启动后最多等待 5 分钟，记录黑屏、Logo、主菜单或实际场景的最远到达点。若进入界面，验证鼠标、左键与 `A` 键，并观察至少 5 分钟。
4. 结束后导出 Winlator 日志、`startup.log` 和游戏根目录中的 `Player-T1-DUCKOV-B.log`。如果 B 轮结果与 A 轮不同，后续用相同 `-logFile` 参数补做 DXVK 对照，以排除日志参数影响。

### T1-DUCKOV-C：补齐保存目录

1. 保持 B 轮的容器、prefix、WineD3D、Box64、图形驱动、分辨率、HUD、环境变量和游戏文件不变。
2. 在 `E:` 根目录创建一个空的 `Saves` 文件夹，即与 `Escape from Duckov` 游戏目录同级；不要在游戏目录内部创建，也不要手工创建 `.sav`、`.tmp` 或 `Options.ES3` 文件。
3. 执行参数仅把日志文件名改为 `-logFile Player-T1-DUCKOV-C.log`，保持相同日志观测方式。保存目录是否存在是本轮唯一预期影响游戏行为的变量。
4. 冷启动并最多等待 5 分钟。记录最远到达点；若进入可交互界面，验证鼠标、左键与 `A` 键并继续观察至少 5 分钟。
5. 结束后导出 Winlator 日志、`startup.log` 和 `Player-T1-DUCKOV-C.log`，同时记录 `E:\Saves` 中是否自动生成了 `Save_1.sav`、`Options.ES3` 或其他文件。

### T1-DUCKOV-D：保留保存目录并回切 DXVK

1. 保留 C 轮创建的 `E:\Saves` 及游戏自动生成的任何内容，不删除或手工修改保存文件；复用同一个容器、prefix 和游戏文件。
2. 只把 DX wrapper 从 WineD3D 切回 DXVK 3.0.2；Wine、Box64、Turnip/Zink、分辨率、HUD 与 `BOX64_UNITYPLAYER=1` 保持不变。

4. 冷启动并最多等待 5 分钟。若进入可交互界面，验证鼠标、左键和 `A` 键，并继续观察至少 5 分钟。
5. 结束后导出 Winlator 日志、`startup.log` 和 `Player-T1-DUCKOV-D.log`。D 轮完成后停止继续调 Duckov，先形成 A-D 对照结论并转测 Palworld；只有证据指向可修复的 Winlator 公共兼容层时，再另立深挖任务。
