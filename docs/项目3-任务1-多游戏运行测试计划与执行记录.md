## 一、任务边界

任务1的目标是形成多款游戏的可复查运行结果，证明已经实际发现并分类兼容性或性能问题。它不要求在这一阶段修复所有发现的问题。

Dave 的启动、稳定性和输入修复属于任务2深度；Dave 的性能基线与优化前后对比属于任务3。两者可以作为任务1的证据来源，但不能替代“各种游戏”的覆盖要求。

## 二、完成标准

满足以下条件后，任务1才标记为完成：

1. 对五款游戏各完成至少一轮有效真机启动测试：Dave the Diver、Stardew Valley、Escape from Duckov、《合金装备5：原爆点》和《师父》。Palworld 当前无法测试，不计入本轮分母。
2. 每款游戏记录主程序、引擎/图形 API、Wine、Box64、图形驱动、DX wrapper、分辨率、环境变量和启动参数。
3. 成功样本至少进入可交互主菜单或实际游戏场景，验证鼠标与一个键盘按键，并持续观察 5 分钟；能进入实际场景时优先观察 10 分钟。
4. 失败样本必须保留可见现象、等待时长和日志，不能只写“打不开”。启动失败、黑屏、闪退、输入异常和低帧率分别分类。
5. 日志、CSV 和截图均使用唯一文件名；归档时记录文件大小与 SHA-256，不覆盖此前样本。
6. 最终形成五游戏测试矩阵，列出通过项、问题项和建议进入任务2/任务3的候选问题，并提交、推送最终节点。原爆点与师父的每项结果都带 `PACKAGE-SCOPED`，只覆盖静态报告中的当前文件指纹。
7. 每轮新导出的运行、输入、性能、测试与构建日志在分析后使用 `scripts/archive-development-logs.ps1` 归档，并与本轮结论和新计划一起推送到 `origin/main`；远程已有相同内容时在清单中引用，仍保留原始路径、大小与 SHA-256 记录。

## 六、结果分类

| 代码 | 分类 | 判定标准 |
|---|---|---|
| PASS-PLAY | 可游玩 | 进入实际场景，鼠标/按键有效，观察期内无闪退 |
| PASS-MENU | 部分通过 | 进入主菜单但未进入场景，或场景加载失败 |
| FAIL-START | 启动失败 | 主程序未创建、命令/路径错误或容器提前退出 |
| FAIL-NO-WINDOW | 无游戏窗口 | 主程序已创建且容器保持运行，但观察期内没有可见游戏窗口或画面 |
| FAIL-BLACK | 黑屏/无首帧 | 进程存在且完成部分初始化，但观察期内无可见画面 |
| FAIL-CRASH | 闪退 | 游戏窗口或主进程出现后异常退出 |
| FAIL-INPUT | 输入异常 | 画面可交互但鼠标或标准按键无响应 |
| PERF-CANDIDATE | 性能候选 | 可以游玩，但持续低帧率、严重帧时间抖动或图形路径效率异常 |
| BLOCKED-PACKAGE | 包体阻断 | 静态检查发现第三方模拟、注入、替换或完整性异常；不运行且不计入兼容性结果 |
