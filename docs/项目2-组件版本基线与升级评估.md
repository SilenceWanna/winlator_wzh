# 项目2：依赖组件版本基线与升级评估

## 二、关键结论

1. **box64 差距最小、最好编**，从它入手（纯 CMake + NDK，本机 NDK r24 已可编）。→ 本项目先做 box64 0.4.0 → 0.4.3。
2. **DXVK / VKD3D 已进入 3.x**（当前 2.x），跨大版本；但它们是 **Windows DLL**，需用 **MinGW-w64** 交叉编译（meson + llvm-mingw），不是 Android NDK。升级价值高但需另搭工具链。
3. **Turnip / Zink 属于 Mesa**，最新 mesa-26.1.5 与当前很接近（turnip 26.1.0）；Mesa 的 Android 交叉编译链最复杂（meson + 大量依赖），升级收益相对小，优先级靠后。
4. **Wine** 独立且最重，升级牵一发动全身（rootfs、wined3d、各种 DLL 兼容），本练习不优先。
5. **Vortek / Gladio 是 brunodev 的私有组件**，无公开源码，无法自行编译升级——只能等上游放出新版 .tzst。

## 三、建议的升级顺序

1. ✅ **box64 0.4.0 → 0.4.3-3**（已进行，见 [[项目2 组件编译篇]]）—— 环境最简单，验证交叉编译流程。
2. **DXVK 2.4.1 → 3.0.2** —— 搭 MinGW 交叉链，收益大（很多游戏图形性能/兼容）。
3. **VKD3D 2.14.1 → 3.0.1** —— 同 DXVK 工具链，顺带做。
4. Turnip / Zink（Mesa）—— 视需要，链最重。
5. Wine —— 最后或不做。

## 四、编译工具链现状（本机）

- Android NDK **r24 (24.0.8215888)**：`aarch64-linux-android21~32-clang` 齐全，含 `android.toolchain.cmake`。→ 够编 box64。
- CMake **3.22.1** + ninja（随 Android SDK）。
- git、Python 3.14。
- **缺**：MinGW-w64 交叉工具链（编 DXVK/VKD3D 需要）、meson（编 DXVK/Mesa 需要）。后续升级 DXVK 时再搭。
