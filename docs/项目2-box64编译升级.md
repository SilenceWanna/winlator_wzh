# 项目2（组件编译篇）：box64 交叉编译与升级 0.4.0 → 0.4.3

> 本篇记录把二进制翻译核心组件 box64 从 winlator 内置的 0.4.0 升级到上游最新 v0.4.3-3 的完整过程，包括交叉编译环境、命令、遇到的问题与解决、集成与验证。这是项目2"编译各组件并升级到最新版"的第一个落地组件。

## 一、为什么先做 box64

见 [[项目2-组件版本基线与升级评估]]：box64 是几个组件里编译最简单的（纯 CMake + Android NDK，无需 MinGW/meson），且当前 0.4.0 与上游 0.4.3-3 差距不大，适合先验证交叉编译流程。

## 二、编译环境

| 工具 | 版本/路径 |
|---|---|
| Android NDK | r24 (24.0.8215888)，`aarch64-linux-android31-clang` |
| CMake | 3.22.1（随 Android SDK） + ninja |
| 源码 | ptitSeb/box64，tag **v0.4.3-3**（commit e2345d7） |
| 目标 | arm64-v8a / android-31 |

## 三、编译步骤

### 1. 拉取源码
```bash
git clone --depth 1 --branch v0.4.3-3 https://github.com/ptitSeb/box64
```

### 2. CMake 配置（参考 box64 官方 release.yml 的 ANDROID 平台）
```bash
cmake -S box64_src -B build_android -G Ninja \
  -DCMAKE_TOOLCHAIN_FILE=<NDK>/build/cmake/android.toolchain.cmake \
  -DANDROID_ABI=arm64-v8a \
  -DANDROID_PLATFORM=android-31 \
  -DANDROID=1 -DARM_DYNAREC=1 -DBAD_SIGNAL=1 \
  -DCMAKE_BUILD_TYPE=RelWithDebInfo
```
关键参数：`-DANDROID=1`（Android 平台）、`-DARM_DYNAREC=1`（开启 ARM64 动态重编译，box64 性能核心）、`-DBAD_SIGNAL=1`（Android 内核信号处理兼容）。

### 3. 编译
```bash
cmake --build build_android -j6
```

## 四、遇到的问题与解决

### 问题：`git_head.h` 生成失败导致 ninja 中断（Windows 特有）
编译进行到 223/577 时报错：
```
[223/577] Generating ../src/git_head.h
FAILED: ../src/git_head.h
cmd.exe /C "... sh -c "echo \#define GITREV ... $(git rev-parse --short HEAD)..."
'sh' is not recognized as an internal or external command
ninja: build stopped: subcommand failed.
```
**根因**：box64 用一条 `sh -c "…git rev-parse…"` 的规则生成记录版本号的 `git_head.h`。在 Windows 的 `cmd.exe` 下 `sh` 不在 PATH，该步骤失败，ninja 随即停止。与 box64 代码无关，纯 Windows 环境问题。

**解决**：把 Git for Windows 自带的 `sh.exe`（`D:\software\Git\usr\bin`）加入 PATH 后续编：
```powershell
$env:PATH = "D:\software\Git\usr\bin;D:\software\Git\cmd;<cmake bin>;$env:PATH"
cmake --build build_android -j6
```
ninja 复用已编译的对象，仅补 `git_head.h`（正确生成 `#define GITREV "e2345d7"`）及剩余部分，最终 `[351/351] Linking C executable box64` 成功。

## 六、strip 与打包

用 NDK 的 `llvm-strip --strip-unneeded` 去符号：
- strip 前 **69.0 MB** → strip 后 **21.8 MB**。

按原 `box64-0.4.0.tzst` 的目录结构（`./usr/local/bin/box64`，权限 0755）用 zstd(level 19) 打包成 `box64-0.4.3.tzst`（**3.21 MB**，比原 0.4.0 的 3.87MB 略小）。

## 七、集成到 winlator

1. 新 tzst 放入 `app/src/main/assets/box64/box64-0.4.3.tzst`，删除旧 `box64-0.4.0.tzst`。
2. 改 `app/src/main/java/com/winlator/core/DefaultVersion.java`：`BOX64 = "0.4.0"` → `"0.4.3"`。
3. 确认无其它硬编码 "0.4.0" 引用（grep 验证）。
4. 运行时逻辑：`GuestProgramLauncherComponent.extractBox64File()` 按 `DefaultVersion.BOX64` 找 assets 里的 `box64-<版本>.tzst` 解压到 `<root>/usr/local/bin/box64`；版本变化时会重新解压（`current_box64_version` 比对）。

## 八、验证

- APK 重新编译（JDK17）：BUILD SUCCESSFUL。
- 待真机验证：安装后启动游戏，box64 日志首行应显示 `Box64 arm64 v0.4.3`（原为 v0.4.0），且游戏正常运行。

## 九、复用到其它组件

box64 的交叉编译流程（NDK toolchain + CMake + strip + 按结构打 tzst + 改 DefaultVersion）可作为后续组件的模板。但注意：
- DXVK/VKD3D 是 Windows DLL，需 **MinGW-w64 + meson**，非 NDK；
- Turnip/Zink 属 Mesa，需 meson + 复杂依赖；
- 各组件 tzst 内部目录结构不同（box64 是 `/usr/local/bin/`，图形驱动是 `/usr/lib/` 等），打包时需对照原包结构。
