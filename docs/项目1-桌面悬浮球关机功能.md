# 项目1：桌面悬浮球关机功能 — 实现报告

## 一、需求

进入 Winlator 虚拟机桌面后，桌面上出现一个悬浮球，点击悬浮球实现关机功能，修改后重新编译一个版本、正常运行，输出修改报告。

**确定的交互设计**：
- 悬浮球：显示"关机"文字的圆形按钮，半透明。
- 可拖动：拖动可改变位置并记忆（重进容器保留位置）。
- 二次确认：点击后弹出确认弹窗，避免误触丢失游戏进度。
- 关机语义：结束当前虚拟机会话、清理 wine/box64 等 guest 进程、返回 Winlator 主界面。

## 二、方案与原理

### 桌面 UI 结构
运行 Windows 容器的桌面是 `XServerDisplayActivity`，其内容区是布局 `xserver_display_activity.xml` 里的 `FrameLayout @id/FLXServerDisplay`。该 FrameLayout 中按 z 序叠加了多层 view：渲染面 `XServerView` → `TouchpadView` → `InputControlsView` → `FrameRating`。悬浮球作为**最后一个子 view** 加入，浮在最上层。

### 复用的拖拽模式
参考现有的 `MagnifierView`（放大镜面板）：它是一个 `FrameLayout`，通过 `setOnTouchListener` 处理 `ACTION_DOWN/MOVE/UP` 实现拖拽，`movePanel()` 做父容器边界钳制，位置持久化到 `SharedPreferences`，`onLayout()` 时恢复。悬浮球沿用这套机制。

### 点击与拖动的区分
悬浮球本身既要能拖、又要能点，因此在 `ACTION_UP` 时用**位移距离**判定：从按下到抬起的位移小于阈值（8dp）视为"点击"→ 触发关机回调；否则视为"拖动"→ 保存新位置。避免二者冲突。

### 关机调用
复用 `XServerDisplayActivity.exit()`（抽屉菜单 "Exit" 用的同一方法）：
1. `winHandler.stop()` — 关闭控制 socket 与 MIDI。
2. `environment.stopEnvironmentComponents()` — 停止所有环境组件（GuestProgramLauncher/XServer/PulseAudio 等），杀掉 box64/wine 进程。
3. `AppUtils.restartApplication(this)` — 以 `Runtime.exit(0)` 结束整个进程（确保所有 guest 子进程随之退出），回到主界面。

这是该 app 既定的、最干净的关机方式；项目中不存在更"优雅的 wine 关机"（如 wineserver -k），此为标准做法。

### 确认弹窗
直接复用现成静态方法 `ContentDialog.confirm(context, msgResId, callback)`，一行接入。

## 三、代码改动

### 新增文件
1. `app/src/main/java/com/winlator/widget/ShutdownBallView.java`
   悬浮球控件。`FrameLayout` 子类，inflate 布局；触摸监听区分拖动/点击；`movePanel()` 边界钳制；`onLayout()` 恢复保存的位置；位置存于 SharedPreferences key `shutdown_ball_view`；暴露 `setOnClickCallback(Runnable)`。

2. `app/src/main/res/layout/shutdown_ball_view.xml`
   56dp 圆形 `TextView`，文字 `@string/shutdown`，背景 `@drawable/shutdown_ball_background`。

3. `app/src/main/res/drawable/shutdown_ball_background.xml`
   `oval` shape，半透明红色填充（`#B3D32F2F`）+ 白色描边。

### 修改文件
4. `app/src/main/res/values/strings.xml`
   新增 `shutdown`（"关机"）、`shutdown_confirm_message`（"确定要关机吗？未保存的进度将丢失。"）。

5. `app/src/main/java/com/winlator/XServerDisplayActivity.java`
   - import `ShutdownBallView`；
   - 新增字段 `private ShutdownBallView shutdownBallView;`；
   - `setupUI()` 末尾创建并 addView，点击回调 = 弹确认弹窗、确认后 `this::exit`。

关键接入代码：
```java
shutdownBallView = new ShutdownBallView(this);
shutdownBallView.setOnClickCallback(() ->
    ContentDialog.confirm(this, R.string.shutdown_confirm_message, this::exit));
rootView.addView(shutdownBallView);
```

## 四、编译

环境要点（详见仓库其它记录）：
- JDK **17**（项目 Gradle 7.3.3 不支持 JDK 21）。
- AGP 7.2.2 / Gradle 7.3.3（保持上游原版，勿被 Android Studio 自动升级）。

命令：
```
JAVA_HOME="<JDK17 路径>"
./gradlew.bat assembleDebug --console=plain
```
产物：`app/build/outputs/apk/debug/app-debug.apk`。

## 五、验证方法

1. 安装 APK，启动一个容器进入桌面。
2. 桌面出现"关机"悬浮球。
3. 拖动悬浮球到别处 → 退出重进容器，位置被记住。
4. 点击悬浮球 → 弹出"确定要关机吗？"。
5. 点确认 → 干净退出、回到 Winlator 主界面（进程结束无残留）；点取消 → 继续留在桌面。
6. 回归：悬浮球只占一个小圆区域，不干扰游戏触控、抽屉菜单、输入控件。

## 六、备注
- 悬浮球常驻桌面（符合"桌面上出现一个悬浮球"的要求）。
- "关机" = 结束虚拟机会话回主界面，与 Android 系统关机无关。
