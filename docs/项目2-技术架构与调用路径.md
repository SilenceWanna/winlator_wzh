# Winlator 技术架构与模块调用路径梳理（项目2 架构篇）

> 基于 winlator_wzh_new（app 11.1，upstream e113da42）源码梳理。所有文件路径相对 `app/src/main/`。
> 本篇为项目2 第一部分（架构与调用路径），组件编译升级部分另见后续文档。

## 0. 总览：Winlator 是什么

Winlator 在 **ARM64 Android** 上运行 **x86/x86_64 Windows 程序**，本质是把多层转换/翻译栈打包进一个 Android app：

```
Windows 程序(.exe, x86)
  → Wine（Windows API → Linux 系统调用）
  → box64（x86 指令 → ARM64 指令，动态二进制翻译）
  → Android 原生进程（运行在一个解压出来的 Linux rootfs 上）
图形另走一条链：D3D/OpenGL → 转 Vulkan → 主机真实 Vulkan → GPU
```

**一个重要架构特点（本 fork）**：**没有 proot 层**。box64+wine 直接作为普通 Android 子进程被 `ProcessBuilder` 启动，"rootfs" 只是 app 私有目录下解压出来的一套文件，靠绝对路径 + `LD_LIBRARY_PATH`/`PATH` 引用，而非 chroot/namespace 隔离。（若对照上游用了 proot 的版本，这是一处显著差异。）

## 1. 组件编排框架

**核心类**：`xenvironment/XEnvironment.java` 持有一个有序的 `ArrayList<EnvironmentComponent>`。
- `addComponent()` 注册组件；`startEnvironmentComponents()`（:55）**按插入顺序**依次 `start()`；`stopEnvironmentComponents()`（:60）反向清理；`onPause/onResume` 广播给各组件（用于画中画挂起/恢复）。
- `EnvironmentComponent`（抽象基类）：`start()`/`stop()` 抽象，`onPause/onResume` 默认空实现。

**组件清单**（`xenvironment/components/`）及职责：

| 组件 | 职责 |
|---|---|
| `SysVSharedMemoryComponent` | 开 SysV 共享内存 unix socket，装 SHMSegmentManager，支撑 MIT-SHM 像素图传输 |
| `XServerComponent` | 开 X11 unix socket（`/tmp/.X11-unix/X0`），处理 X 客户端连接（含 fd 传递） |
| `NetworkInfoUpdateComponent` | 写 `ifaddrs`/`hosts`，监听网络变化 |
| `ALSAServerComponent` / `PulseAudioComponent` | 音频服务端（二选一），后者拉起原生 `libpulseaudio.so` 守护进程 |
| `VortekRendererComponent` | **默认 Vulkan 渲染器**，加载 `libvortekrenderer`，把真实 Vulkan 暴露给 guest |
| `VirGLRendererComponent` | OpenGL/VirGL 渲染器，`libvirglrenderer`，帧缓冲回刷到 GL 纹理 |
| `GuestProgramLauncherComponent` | **启动 box64**，跑 `box64 wine explorer …`。**最后启动**，确保前面各 IPC 服务端已就绪 |

**启动顺序**（`XServerDisplayActivity.setupXEnvironment()` :511-546）：
`SysVSHM → XServer → NetworkInfo → ALSA/Pulse → Vortek → VirGL → GuestProgramLauncher`
—— 先把所有 IPC 服务端拉起来监听，最后才启动 guest，避免 guest 连接时服务端未就绪。

## 2. rootfs / 容器模型

- **rootfs**：`RootFS.java` —— 位于 `filesDir/rootfs`，由 `rootfs.tzst`（asset）解压而来（`RootFSInstaller` install:47-78）。含 `xuser` 用户、`WINEPREFIX=/home/xuser/.wine`。
- **容器**：`ContainerManager.java` —— 每个容器在 `rootfs/home/xuser-<id>`，配置存 `.container` JSON。创建时解压 `container_pattern.tzst` + 拷贝公共 DLL。`activateContainer()` 把 `home/xuser` 软链到 `xuser-<id>`（多容器切换）。
- **drive_c**：容器内 `.wine/drive_c` 即 Windows 的 C 盘。
- **隔离方式**：无 proot/chroot，靠绝对路径 + 环境变量。`ProcessHelper.exec()`（:65）是普通 `ProcessBuilder`，`directory=rootDir`，通过反射抓取 Linux pid。

## 3. 【重点】二进制翻译模块调用路径（box64）

### 3.1 启动链（Java → box64 → wine → exe）
入口 `GuestProgramLauncherComponent.start()`（:35）在锁内执行：`stop()`(杀旧pid) → `extractBox64File()`(:118) → `copyDefaultBox64RCFile()`(:130) → `pid = execGuestProgram()`(:40)。

`execGuestProgram()`（:86）构建环境并拼命令：
- **环境变量**（:90-103）：`addBox64EnvVars()`(:136) 设 `BOX64_NOBANNER/DYNAREC=1/UNITYPLAYER=0` + 日志开关 + 合并预设 + `BOX64_RCFILE=<root>/etc/config.box64rc`；再设 `HOME`、`USER=xuser`、`DISPLAY=:0`、`PATH=<root>/opt/wine/bin:...`、`LD_LIBRARY_PATH=<root>/usr/lib`、`BOX64_LD_LIBRARY_PATH=<root>/lib/x86_64-linux-gnu`、`ANDROID_SYSVSHM_SERVER`(共享内存socket)，并合并调用方在 `setupXEnvironment()`(:481-544) 设的 `WINEPREFIX/WINEDEBUG/DXVK/*驱动` 变量。
- **命令**（:108）：`<root>/usr/local/bin/box64 <guestExecutable>`，其中 guestExecutable（来自 :500）= `wine explorer /desktop=nogui,<分辨率> <getWineStartCommand()>`。

完整执行链：
```
<root>/usr/local/bin/box64  wine explorer /desktop=nogui,WxH  C:\...\game.exe
```
经 `ProcessHelper.exec()`（`core/ProcessHelper.java:65`，ProcessBuilder，directory=rootDir）直接启动，无 proot 包装。

### 3.2 box64 调优
两套机制：
1. **预设**（`box64/Box64PresetManager.java:18`）：`STABILITY / CONSERVATIVE / INTERMEDIATE(默认) / PERFORMANCE / CUSTOM`，各自设一组 `BOX64_DYNAREC_*`。关键旋钮含义：
   - `SAFEFLAGS`(0/1/2)：x86 标志位重算的谨慎程度；
   - `BIGBLOCK`(0-3)：翻译块融合的激进程度（越大越快、越可能出错）；
   - `CALLRET`：原生 call/ret 优化；
   - `STRONGMEM`(0-2)：在弱内存序的 ARM 上模拟 x86 强内存序的强度；
   - `FASTNAN/FASTROUND/X87DOUBLE`：浮点保真 vs 速度。
   - PERFORMANCE 放松正确性求速度；STABILITY 收紧。
2. **`.box64rc`**：`assets/box64/default.box64rc` 拷到 `/etc/config.box64rc`，做 per-exe 覆盖（如 `[witcher3.exe] STRONGMEM=1`）。

### 3.3 box64 二进制来源
**预编译，不在本仓库编译**。来自 `assets/box64/box64-0.4.0.tzst`（版本 `DefaultVersion.BOX64="0.4.0"`），按需解压到 `<root>/usr/local/bin/box64`。`cpp/CMakeLists.txt` 只编 winlator/vortek/virgl/midi/adrenotools/gladio 渲染器，**不含 box64/wine 源码**。
> 这对项目2"编译各组件"很关键：box64/wine/dxvk 等都是**外部预编译产物**打包进 assets，升级 = 换 .tzst，真正"编译"需到各自上游源码仓库交叉编译。

### 3.4 进程生命周期
静态 `pid` 跟踪 box64 根进程；`stop()` 用 `Process.killProcess(pid)`。画中画挂起：`onPause()` 遍历 `/proc` 找 wine/.exe 子进程并 `SIGSTOP`，`onResume()` 发 `SIGCONT`。

## 4. 【重点】渲染模块调用路径（D3D/GL → Vulkan → GPU）

分五跳，核心是**共享内存环形缓冲跨越 guest/host 边界**。

### Hop 1：DirectX → Vulkan/GL 包装层（guest 内）
- **选择**：`container/DXWrappers.java` 定义 `DXVK/WINED3D/VKD3D/CNC_DDRAW/D7VK`。
- **安装**：`XServerDisplayActivity.extractDXWrapperFiles()`(:800-877) 把对应 DLL（d3d11.dll/dxgi.dll 等）解压进 `drive_c/windows`。
- **DLL 覆盖**：`core/WineUtils.java:94-138` 写注册表 `DllOverrides = native,builtin`，强制 wine 加载包装 DLL。
- **分工**：DXVK(D3D→Vulkan)、VKD3D(D3D12→Vulkan)、WineD3D(D3D→OpenGL)。

### Hop 2：图形驱动层（guest）
`extractGraphicsDriverFiles()`(:713-775)：默认 Vortek（Adreno 则 Turnip），解压 guest ICD + `libvulkan_vortek.so` 到 rootfs。OpenGL 驱动：Zink 设 `GALLIUM_DRIVER=zink`、VirGL 设 `virpipe`、Gladio 设 `GLADIO_NO_ERROR`。
> 项目3 已验证：OpenGL 游戏用 Gladio 会因 GL 版本上限 3.3 失败，需换 Zink。见 [[项目3 兼容性案例]]。

### Hop 3：guest/host 边界 —— Unix sockets
`xconnector/UnixSocketConfig.java:11-13`：X server `/tmp/.X11-unix/X0`、Vortek `/tmp/.vortek/V0`、VirGL `/tmp/.virgl/V0`。host 端监听器在 `setupXEnvironment()` 注册。guest 的 ICD/Gallium 驱动连到这些 socket。

### Hop 4：Vortek（默认 Vulkan）host 端
- 组件 `VortekRendererComponent` 加载 `libvortekrenderer`，`initVulkanWrapper` 打开真实驱动；收到建上下文请求调 native `createVkContext(fd, options)`。
- native 入口 `cpp/vortekrenderer/src/main.c:42-65`；`openVulkanLibrary` dlopen 设备真实 `libvulkan`，或经 `adrenotools_open_libvulkan` 加载自定义 Adreno 驱动。
- **传输 = 共享内存环形缓冲，而非 socket 负载**：`vk_context.c setupRingBuffers`(:85-104) 建两块 ashmem（server/client ring），把 FD 经 unix socket `send_fds` 交给 guest。`requestHandlerThread` 从 ring `vt_recv` 取命令分发。
- **重放**：`request_handler.c` 反序列化每条命令，调**真实**驱动（`vkCreateInstance` 等），对象按 ID 代理。
- **呈现**：`xwindow_swapchain.c` 把窗口的 `AHardwareBuffer` 经 `VK_ANDROID_external_memory_android_hardware_buffer` 导入为 `VkImage`。

### Hop 5：屏幕输出（host GLES 合成）
`renderer/GPUImage.java` 把那块 AHardwareBuffer 包装成 EGLImage/GL 纹理；`renderer/GLRenderer.java`（GLSurfaceView.Renderer）把所有窗口纹理合成到 `XServerView`。OpenGL guest 则由 `VirGLRendererComponent.flushFrontbuffer` 把 VirGL 帧缓冲拷进纹理。

### 端到端总链
```
游戏 D3D11 调用
 → DXVK (guest DLL, D3D→Vulkan)
 → guest libvulkan_vortek.so (ICD)
 → 序列化进【共享内存环形缓冲】(FD 经 unix socket /tmp/.vortek/V0 交接)
 →━━━ GUEST / HOST 边界 ━━━
 → vortekrenderer host 线程 vt_recv → 反序列化
 → 真实 libvulkan（或 adrenotools Adreno 驱动）
 → Adreno/Mali GPU
渲染结果存于共享 AHardwareBuffer（Vortek 视为 VkImage，GLRenderer 视为 GL 纹理）→ 合成到屏幕 XServerView
```
（D3D12 走 VKD3D→Vulkan 同路径；WineD3D→OpenGL 与 Zink/VirGL/Gladio 走 `/tmp/.virgl/V0` + flushFrontbuffer。）

## 5. IPC 机制汇总

| 机制 | 路径/端口 | 承载 |
|---|---|---|
| XConnector unix socket | `/tmp/.X11-unix/X0` | X11 协议 + fd 传递 |
| | `.vortek/V0`、`.virgl/V0` | 渲染命令流（+ 共享内存 FD 交接） |
| | `.sysvshm/SM0`、`.sound/AS0`/`PS0` | 共享内存 / 音频 |
| SysV 共享内存 | native segments | MIT-SHM 图像/像素图传输 |
| winhandler 控制 socket | UDP loopback :7947/:7946 | EXEC、KILL/LIST 进程、鼠标/键盘/手柄注入、剪贴板 |

## 6. 启动时序（`XServerDisplayActivity.onCreate()` :142）

1. 主题/UI + inflate 布局；PreloaderDialog。
2. `RootFS.find`(:166)；`ContainerManager` + `activateContainer`(:169-171)；wineprefix 更新检查。
3. 加载容器 graphics/audio/dxwrapper/screen 配置，套用快捷方式覆盖。
4. 建 `XServer`，挂 `WinHandler` 与窗口监听；`setupUI()` 建 `XServerView`/GLRenderer。
5. 后台线程：`setupWineSystemFiles` → `extractGraphicsDriverFiles` → `changeWineAudioDriver` → `setupXEnvironment`。
6. `setupXEnvironment` 按序加组件 → `startEnvironmentComponents()` → `winHandler.start()`。
7. guest 命令：`wine explorer /desktop=… C:\windows\winhandler.exe <exe>`。

## 7. 对项目2 组件编译的启示

- box64、wine、dxvk、vkd3d、turnip、vortek 等**运行时组件都是预编译产物**（`assets/box64/*.tzst`、`assets/graphics_driver/*.tzst`、`assets/imagefs`→rootfs 等），app 编译时不重编它们。
- 本仓库 `cpp/` 里**用源码编译的**只有 winlator/vortekrenderer/virglrenderer/gladiorenderer/midihandler/libadrenotools 这几个 JNI 原生库。
- 因此"编译并升级各组件"要到**各自上游仓库**（box64、DXVK、dav1d/mesa-turnip 等）用 Android NDK 交叉编译，产出 .so 打成 .tzst，再替换 assets 里的对应文件、更新 `DefaultVersion` 版本号。这是项目2 第二部分的工作。
